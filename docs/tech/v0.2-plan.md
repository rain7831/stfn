# STFN v0.2 规划

> 状态：待审核（尚未开始写代码）
> 目标：英文音标/发音、系统主题、输入聚焦、niri 选区翻译
> 关联：`docs/tech/architecture.md`、`ui.md`、`settings.md`、`providers.md`
>
> 说明：v0.1 文档中的“v1.1”音标/朗读占位由本计划取代。

## 0. 已确认决策

- **只做英文音标/发音**，不做中文拼音。
- **英译中**：音标和发音显示在输入框下方（输入区内部）。
- **中译英**：每个厂商的结果卡片内，在“厂商标题”和“译文”之间显示音标/发音，位置略靠近厂商标题。
- 音标/发音**仅单词级**；句子/短语不展示音标。
- **厂商 API 本身不返回 IPA**：Bing/火山/阿里只返回译文。v0.2 需要引入一个英文词典查询源，否则中译英结果没有音标可展示。
- 选区翻译**只读 primary selection**；读不到就提示，不回退普通剪贴板、不发送 Ctrl+C。
- 两项都进入 **v0.2.0**：四项功能一起交付。

## 1. 英文音标与发音

### 1.1 数据来源

- 音标：`https://api.dictionaryapi.dev/api/v2/entries/en/<word>`（免费、无 key）。
  - 返回 `phonetics[]`，包含 `text`（IPA）和 `audio` URL。
  - 仅对英文单词有效；短语/句子会 404，直接隐藏。
  - 数据为 CC BY-SA 3.0，音频为 CC BY / BY-SA；README/设置页需要 attribution。
- 发音：
  - 优先使用 dictionaryapi 的真人音频（如有）。
  - 缺失时用 Edge TTS 兜底（`msedge-tts`，非官方、无 key）；US/UK 分别用 en-US/en-GB 音色。
  - 播放使用 `rodio`；音频按 `(word, accent)` 内存缓存；失败时隐藏播放按钮，不影响译文。
- 不引入拼音库；中文文本不产生任何音标。

### 1.2 展示规则

#### 英译中

```text
输入中文或英文，自动翻译              EN → 中
┌────────────────────────────────────────┐
│ hello                                  │
└────────────────────────────────────────┘
US /həˈloʊ/  ▶      UK /həˈləʊ/  ▶
```

- 输入区卡片下方新增一行 accent 信息，位于输入卡片和分割线之间。
- 只有输入是**单个英文单词**且词典命中时显示。
- 两个 accent 各自显示 IPA + 播放；只有一个可用时只显示一个。
- 无 IPA/无音频时不占位；不显示错误。

#### 中译英

```text
翻译结果
┌────────────────────────────────────────┐
│ Bing                                   │
│ US /həˈloʊ/ ▶   UK /həˈləʊ/ ▶          │
│ Hello                                  │
└────────────────────────────────────────┘
```

- 在 `ProviderRow` 的 header 和 body 之间插入 accent 行，margin-top 小、margin-bottom 小，靠近厂商标题。
- 每个结果卡片单独查询自己的英文译文；只有译文是单词且词典命中时显示。
- 不同厂商返回不同译文时，各自显示各自的音标；相同译文可重复，但不共享 UI 行。
- 无命中时该卡片不显示 accent 行。

### 1.3 数据结构

```rust
enum Accent { Us, Uk }

struct AccentPronunciation {
    ipa: Option<String>,
    audio: Option<AudioSource>,
}

struct Pronunciation {
    us: Option<AccentPronunciation>,
    uk: Option<AccentPronunciation>,
}

enum AudioSource {
    Dictionary(String), // URL
    EdgeTts { voice: String },
}
```

- 词典查询结果按 word 缓存（LRU，容量 256，TTL 24h 可仅内存）。
- 音频按 `(word, accent, source)` 缓存字节。
- 查询失败、超时、非单词：返回 `None`，UI 不显示。
- 新增 `pronunciation` 模块，不把音标逻辑塞进 provider；provider 仍只负责翻译。

### 1.4 时序

```text
翻译结果返回
  ├─ 英译中：对输入英文单词查询 Pronunciation -> 更新输入区 accent 行
  └─ 中译英：对每个结果的英文译文查询 Pronunciation -> 更新对应卡片 accent 行
点击播放
  ├─ 命中内存音频缓存 -> 直接 rodio 播放
  ├─ 词典 audio URL -> 下载并缓存
  └─ 无词典音频 -> Edge TTS -> 缓存并播放
```

- 查询与下载都在后台 runtime，不阻塞 GTK 主线程。
- 卡片 accent 行加载中不显示 spinner，避免结果区跳动；查到后再显示。
- 播放按钮在播放中可切换为停止/加载态。

## 2. 系统主题

- 使用 `AdwStyleManager` 跟随系统；默认 `color-scheme=default`。
- 清理/检查硬编码颜色：现有主界面主要使用 libadwaita 主题色与 `.card`/`.accent`/`.error` class。
- 验收：
  - 浅色/深色切换时输入卡片、结果卡片、错误文本、按钮、logo 背景正常；
  - 高对比度主题下文字可读；
  - 不增加手动浅色/深色开关（v0.2 范围外）。

## 3. 打开时聚焦输入框

- `connect_activate` 中 present 后：
  - 立即 `input.grab_focus()`；
  - 再用 `glib::idle_add_local_once` 补一次焦点，覆盖首次 map 的时序问题。
- 从设置页返回主页面时重新聚焦输入框。
- 选区翻译注入文本后聚焦输入框。
- 验收：启动后不点击直接输入；`stfn` 第二次启动聚焦已有窗口；`stfn selection` 注入后可直接编辑。

## 4. niri 选区翻译

### 4.1 交互

推荐 niri 绑定：

```kdl
binds {
    Mod+Shift+T { spawn "stfn"; }
    Mod+Shift+Y { spawn "stfn" "selection"; }
}
```

- `Mod+Shift+Y` 在 niri 默认配置和当前 `bind.kdl` 中未占用。
- `Mod+Shift+T` 仍用于普通打开窗口。

### 4.2 流程

```text
用户选中文本
  -> Mod+Shift+Y
  -> spawn "stfn" "selection"
  -> 第二个进程通过 GApplication command-line 转发到主实例
  -> 主实例读取 primary selection
       ├─ 有文本：写入输入框 -> 聚焦 -> translate_now()（跳过 debounce）
       └─ 无文本：状态提示“没有读到选中文本”
```

- 读取使用 GTK4：
  ```rust
  let display = gtk::gdk::Display::default();
  let clipboard = display?.primary_clipboard();
  let text = clipboard.read_text_future().await?;
  ```
- 不引入 `wl-clipboard` 外部依赖。
- 超过 5000 字符：截断或提示；沿用 CLI 上限。
- 选区文本保留换行；输入法/光标在文末。
- 不写剪贴板、不覆盖用户剪贴板。

### 4.3 单实例与设置页

- 把当前 `open_settings: bool` 扩展为：
  ```rust
  enum GuiIntent {
      Open,
      Settings,
      Selection,
  }
  ```
- `connect_command_line` 解析 `settings` / `selection`，写入 pending intent；`connect_activate` 在窗口存在或新建后处理。
- 设置页打开时收到 selection：
  - 设置页无未保存修改：`nav.pop_to_page(main_page)` 后注入文本；
  - 设置页有未保存修改：不静默丢弃，保持设置页并提示“先保存或取消设置”。
- 需要把 `main_page` 存到 `UiState`，便于 `pop_to_page`。

### 4.4 边界

- primary selection 依赖应用主动设置；浏览器、GTK/Qt、终端通常支持，部分 Electron/特殊应用可能不支持。
- 不支持时只提示，不回退普通剪贴板，不用 `wtype` 发送 Ctrl+C。
- 不做通用 Wayland 方案；仅面向 niri。
- niri 已支持 primary selection；`wl-paste --primary` 与 GTK `primary_clipboard` 本机验证可用。

## 5. 架构改动

| 模块 | 改动 |
| --- | --- |
| `src/pronunciation.rs` | 新增：词典查询、IPA/音频解析、缓存、Edge TTS 兜底 |
| `src/tts.rs` | 新增：Edge TTS 请求与音频缓存；`rodio` 播放 |
| `src/ui/mod.rs` | 输入区/结果卡片 accent 行；focus idle；selection intent |
| `src/cli.rs` | `selection` 子命令；`--speak` 接入 TTS（若 v0.2.0 实现） |
| `src/main.rs` | `Mode::Gui` 携带 `GuiIntent` |
| `Cargo.toml` | `rodio`、`msedge-tts`（或等价）；词典请求复用 reqwest |
| `README.md` | v0.2 路线图、`Mod+Shift+Y` 示例、词典/TTS attribution |

- 词典查询和 TTS 都走现有 tokio runtime 与 reqwest client。
- 音频播放不要阻塞 UI 线程；`rodio` 输出流在独立线程/设备上。
- 不把音标字段塞进 `TranslateOutput`（provider 不返回）；`Pronunciation` 是后处理服务。
