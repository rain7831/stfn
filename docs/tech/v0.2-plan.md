# STFN v0.2 规划

> 状态：v0.2.0 主体已实现；“句子级 Edge TTS 朗读”和“手动浅色/深色覆盖”新增到 v0.2.0，待实现
> 目标：英文音标/发音、单词/句子级朗读、系统/手动主题、输入聚焦、niri 选区翻译
> 关联：`docs/tech/architecture.md`、`ui.md`、`settings.md`、`providers.md`
>
> 详细设计：`pronunciation.md`、`selection.md`
>
> 说明：v0.1 文档中的“v1.1”音标/朗读占位由本计划取代。
> v0.2 同时取消 v0.1 的 GApplication 单实例模型，改为每次启动新进程。
> v0.2.1 不再计划其他功能；原“TTS 音色/语速设置”和“wtype Ctrl+C 回退”取消。

## 0. 已确认决策

- **只做英文音标/发音**，不做中文拼音。
- **英译中**：音标和发音显示在输入框下方（输入区内部）。
- **中译英**：每个厂商的结果卡片内，在“厂商标题”和“译文”之间显示音标/发音，位置略靠近厂商标题。
- **音标仅单词级**；句子/短语不展示音标，但 v0.2.0 支持 Edge TTS 整句朗读。
- **厂商 API 不返回英文 IPA**：Bing 的 `ttranslatev3`/`tlookupv3` 返回的是中文 pinyin `transliteration`，不是英文 IPA；火山/阿里只返回译文。v0.2 需要引入英文词典查询，否则中译英结果没有音标可展示。
- 选区翻译**只读 primary selection**；读不到就提示，不回退普通剪贴板、不发送 Ctrl+C。
- **取消单实例**：每次 `stfn` / `stfn settings` / `stfn selection` 都启动新进程和独立窗口；短生命周期，关闭即退出。
- 四项基础能力、**句子级 Edge TTS 全文朗读**、**手动浅色/深色覆盖**都进入 **v0.2.0**。
- 单词音频优先词典真人音频，失败后优先有道词典发音，最后才用 Edge TTS；音频只在内存缓存，不落盘。

## 1. 英文音标与发音

### 1.0 Bing 调研结论

- `ttranslatev3` 英译中会返回：
  ```json
  {"translations":[{"text":"你好","transliteration":{"text":"Nǐ hǎo","script":"Latn"}}]}
  ```
  这是**中文结果的拼音**，不是英文 IPA。
- `ttranslatev3` 中译英会返回 `inputTransliteration`（中文输入的拼音），也不是英文 IPA。
- `tlookupv3` 的 `translations[].transliteration` 同样是中文拼音。
- Bing 词典网页 `/dict/search` 的音频/音标靠前端 JS，没有稳定的官方 JSON API；不采用 HTML 抓取。
- 结论：**三家 provider 都不提供英文 IPA**；v0.2 使用 `dictionaryapi.dev` 做英文单词查询，属于后处理/降级，不是 provider 能力。

### 1.1 数据来源

- 音标：`https://api.dictionaryapi.dev/api/v2/entries/en/<word>`（免费、无 key）。
  - 返回 `phonetics[]`，包含 `text`（IPA）和 `audio` URL。
  - 仅对英文单词有效；短语/句子会 404，音标行隐藏，但整句朗读仍可用（见 §1.5）。
  - 数据为 CC BY-SA 3.0，音频为 CC BY / BY-SA；README/设置页需要 attribution。
- 发音：
  - 优先使用 dictionaryapi 的真人音频（如有）。
  - 词典缺失音频或下载失败时，优先用有道词典发音（`dict.youdao.com/dictvoice`）：US `type=1`，UK `type=2`。
  - 有道也失败时用 Edge TTS 兜底（`msedge-tts`，非官方、无 key）；US/UK 分别用 en-US/en-GB 音色。
  - 播放使用 `rodio`，Linux 上优先选 cpal 的 PipeWire/PulseAudio 设备，避免绕过系统混音器。
  - 音频只缓存内存：LRU 64 条 + 8MiB 总字节 + 1h TTL；不写磁盘，退出即清空。
  - 词典命中后预加载可见 accent 的音频；预加载与点击共享单飞请求；失败保留播放按钮供重试。
- 不引入拼音库；中文文本不产生任何音标。

### 1.2 展示规则

#### 英译中

```text
输入中文或英文，自动翻译              EN → 中
┌────────────────────────────────────────┐
│ hello                                  │
└────────────────────────────────────────┘
US /həˈloʊ/  ▶      UK /həˈləʊ/  ▶
```

- 输入区卡片下方新增一行 accent 信息，位于输入卡片和分割线之间。
- 只有输入是**单个英文单词**且词典命中时显示。
- 两个 accent 各自显示 IPA + 播放；只有一个可用时只显示一个。
- 无 IPA/无音频时不占位；不显示错误。

#### 中译英

```text
翻译结果
┌────────────────────────────────────────┐
│ Bing                                   │
│ US /həˈloʊ/ ▶   UK /həˈləʊ/ ▶          │
│ Hello                                  │
└────────────────────────────────────────┘
```

- 在 `ProviderRow` 的 header 和 body 之间插入 accent 行，margin-top 小、margin-bottom 小，靠近厂商标题。
- 每个结果卡片单独查询自己的英文译文；只有译文是单词且词典命中时显示。
- 不同厂商返回不同译文时，各自显示各自的音标；相同译文可重复，但不共享 UI 行。
- 无命中时该卡片不显示 accent 行。
- 不在输入框和结果之间放一条共享音标行：中译英的各厂商译文可能不同，共享行无法表达这种差异；英译中的共享行只针对源英文单词，位置在输入卡片下方。

### 1.3 数据结构

```rust
enum Accent { Us, Uk }

struct AccentPronunciation {
    ipa: Option<String>,
    audio: Option<AudioSource>,
}

struct Pronunciation {
    us: Option<AccentPronunciation>,
    uk: Option<AccentPronunciation>,
}

enum AudioSource {
    Dictionary(String), // URL
    EdgeTts { voice: String },
}
```

- 词典查询结果按 word 缓存（LRU，容量 256，TTL 24h 可仅内存）。
- 音频按 `(word, accent, source)` 缓存字节。
- 查询失败、超时、非单词：返回 `None`，UI 不显示。
- 新增 `pronunciation` 模块，不把音标逻辑塞进 provider；provider 仍只负责翻译。

### 1.4 时序

```text
翻译结果返回
  ├─ 英译中：对输入英文单词查询 Pronunciation -> 更新输入区 accent 行
  └─ 中译英：对每个结果的英文译文查询 Pronunciation -> 更新对应卡片 accent 行
  └─ 查词结果返回后：后台预加载可见 accent 的音频（US -> UK 串行）
点击播放
  ├─ 命中内存音频缓存 -> 直接 rodio 播放
  ├─ 预加载仍在进行 -> 等待同一个单飞请求 -> 播放
  ├─ 词典 audio URL -> 下载并缓存
  ├─ 词典失败/缺失 -> 有道 -> 缓存并播放
  └─ 有道失败 -> Edge TTS -> 缓存并播放
```

- 查询与下载都在后台 runtime，不阻塞 GTK 主线程。
- 卡片 accent 行加载中不显示 spinner，避免结果区跳动；查到后再显示。
- 播放按钮在播放中可切换为停止/加载态。

### 1.5 句子级朗读（v0.2.0）

- 只做英文全文朗读，不产生句子级 IPA；音标仍只针对单词。
- 触发位置：
  - 英译中：输入是英文且不是单个单词时，在输入卡片下方显示“朗读原文”按钮；单词继续使用词典音标/发音。
  - 中译英：某个厂商译文是英文且不是单个单词时，在该结果卡片 header（复制按钮旁）显示“朗读译文”按钮；单词继续使用 accent 行。
- 合成使用 Edge TTS，默认 US 音色；不提供音色/语速设置。
- 不预加载句子音频；点击后合成并播放，按钮显示加载/播放/重试状态。
- 播放复用现有独立音频线程和 PipeWire 路由，同一时间只播一条。
- 失败不隐藏按钮，保留重试；不弹出全局错误。
- CLI `--speak` 已覆盖完整译文朗读，维持现状。


## 2. 系统主题与手动覆盖

- 使用 `AdwStyleManager`；默认 `color-scheme=default`（跟随系统）。
- 新增手动覆盖：`general.color_scheme = "default" | "light" | "dark"`。
- 设置页新增“外观”组，提供“跟随系统 / 浅色 / 深色”三选一；保存后立即通过 `AdwStyleManager` 生效，无需重启。
- 配置缺省或非法值回退 `default`，并记录 warning。
- 清理/检查硬编码颜色：现有主界面主要使用 libadwaita 主题色与 `.card`/`.accent`/`.error` class。
- 验收：
  - 浅色/深色切换时输入卡片、结果卡片、错误文本、按钮、logo 背景正常；
  - 高对比度主题下文字可读；
  - 手动选择后重启仍保持，选“跟随系统”恢复系统主题。

## 3. 打开时聚焦输入框

- `connect_activate` 中 present 后：
  - 立即 `input.grab_focus()`；
  - 再用 `glib::idle_add_local_once` 补一次焦点，覆盖首次 map 的时序问题。
- 从设置页返回主页面时重新聚焦输入框。
- 选区翻译注入文本后聚焦输入框。
- 验收：每次启动新窗口后不点击直接输入；`stfn selection` 注入后可直接编辑。

## 4. niri 选区翻译

### 4.1 交互

推荐 niri 绑定：

```kdl
binds {
    Mod+Shift+T { spawn "stfn"; }
    Mod+Shift+Y { spawn "stfn" "selection"; }
}
```

- `Mod+Shift+Y` 在 niri 默认配置和当前 `bind.kdl` 中未占用。
- `Mod+Shift+T` 仍用于普通打开窗口。

### 4.2 流程

```text
用户选中文本
  -> Mod+Shift+Y
  -> spawn "stfn" "selection"
  -> 新进程启动独立窗口
  -> 读取 primary selection
       ├─ 有文本：写入输入框 -> 聚焦 -> translate_now()（跳过 debounce）
       └─ 无文本：状态提示“没有读到选中文本”
```

- 读取使用 GTK4：
  ```rust
  let display = gtk::gdk::Display::default();
  let clipboard = display?.primary_clipboard();
  let text = clipboard.read_text_future().await?;
  ```
- 不引入 `wl-clipboard` 外部依赖。
- 超过 5000 字符：直接拒绝，不填入、不翻译，并提示。
- 选区文本保留换行；输入法/光标在文末。
- 不写剪贴板、不覆盖用户剪贴板。

### 4.3 进程模型与设置页

- **取消单实例**：`adw::Application` 使用 `gio::ApplicationFlags::NON_UNIQUE`，不再注册 command-line 转发、不再维护 `state_slot`。
- 每次启动都由 clap 解析一个进程意图：
  ```rust
  enum GuiIntent {
      Open,
      Settings,
      Selection,
  }
  ```
- `main.rs` 解析意图后调用 `ui::run(intent)`；进程内只创建一个 `UiState` 和一个窗口。
- `stfn settings` 新进程直接构建主页面并 push 设置页；返回可回到主页面。
- `stfn selection` 新进程直接读取 primary selection，不存在“另一个实例的设置页有未保存修改”的问题。
- 多进程会重复 GTK/runtime 内存占用，但窗口短生命周期，符合当前工具定位。

### 4.4 边界

- primary selection 依赖应用主动设置；浏览器、GTK/Qt、终端通常支持，部分 Electron/特殊应用可能不支持。
- 不支持时只提示，不回退普通剪贴板，不用 `wtype` 发送 Ctrl+C。
- 不做通用 Wayland 方案；仅面向 niri。
- niri 已支持 primary selection；`wl-paste --primary` 与 GTK `primary_clipboard` 本机验证可用。

## 5. 架构改动

| 模块 | 改动 |
| --- | --- |
| `src/pronunciation.rs` | 新增：词典查询、IPA/音频解析、预加载、音频缓存、Youdao/Edge TTS 兜底 |
| `src/tts.rs` | 新增：Edge TTS 请求、PipeWire 音频播放、句子级朗读 |
| `src/ui/mod.rs` | 输入区/结果卡片 accent 行；句子朗读按钮；focus idle；selection 注入；主题手动覆盖；移除单实例逻辑 |
| `src/config.rs` | 新增 `general.color_scheme` 读写与校验 |
| `src/cli.rs` | `selection` 子命令；`GuiIntent`；`--speak` 接入 TTS |
| `src/main.rs` | `Mode::Gui` 携带 `GuiIntent`；`NON_UNIQUE` 应用 |
| `Cargo.toml` | `rodio`、`msedge-tts`（或等价）；词典请求复用 reqwest |
| `README.md` | v0.2 路线图、`Mod+Shift+Y` 示例、词典/TTS attribution |

- 词典查询和 TTS 都走现有 tokio runtime 与 reqwest client。
- 音频播放不要阻塞 UI 线程；`rodio` 输出流在独立线程/设备上。
- 不把音标字段塞进 `TranslateOutput`（provider 不返回）；`Pronunciation` 是后处理服务。

## 8. 已确认决策

1. `dictionaryapi.dev` 作为英文单词音标/真人音频源；做 CC BY-SA attribution。
2. 单词音频顺序：词典真人音频 -> 有道词典发音 -> Edge TTS；音频只缓存内存，不落盘。
3. 选区快捷键使用 `Mod+Shift+Y`。
4. 中译英始终按每个结果卡片显示音标/发音，不做共享行；英译中在输入框下方显示源单词。
5. 句子级只做 Edge TTS 全文朗读，不产生句子级 IPA，不提供音色/语速设置。
6. v0.2 取消单实例，每次启动新进程和独立窗口。
7. 单词音频只缓存内存（LRU 64 + 8MiB + 1h），不落盘。
8. 查词后预加载可见 accent 的音频；点击等待同一个单飞请求。
9. 手动主题覆盖使用 `general.color_scheme = default|light|dark`，设置页即时生效。
10. v0.2.1 不再计划其他功能。
